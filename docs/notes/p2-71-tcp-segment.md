# フェーズ2-71 自作 TCP(1):セグメントとチェックサム

## 何をしたか

ADR-0006 の「smoltcp の TCP を自作と差し替えて比べる」を始めた。差し替えるのは TCP だけで、IP・ARP・DHCP・UDP は smoltcp のまま使う。smoltcp の raw ソケット(`IpProtocol::Tcp`)に TCP のパケットを受け取らせると、smoltcp は TCP を自分で処理せず、RST も返さない(`handled_by_raw_socket`)。これで、IP より下は動くものを使ったまま、TCP だけを一から組める。

進め方:

1. セグメントとバイト列の行き来、チェックサム(今回)
2. シーケンス番号の比べ方と、接続の状態遷移(3 ウェイハンドシェイク → データ → FIN)
3. 再送(RTO)とウィンドウ
4. raw ソケットで `Stack` につなぎ、smoltcp の TCP と起動時に切り替えて、同じテストを通す

今回足したもの:`kernel/src/net/tcp/segment.rs`

- `Segment`:ポート、シーケンス番号、確認応答番号、フラグ(FIN・SYN・RST・PSH・ACK)、ウィンドウ、MSS オプション、データ
- `Segment::emit` / `Segment::parse`:ヘッダは 20 バイト + オプション。4 バイト目から 12 バイト目の上位 4 ビットが「データオフセット」で、ヘッダの長さを 4 バイト単位で表す。オプションは「種類・長さ・中身」の並びで、知らない種類は長さの分だけ飛ばす(ウィンドウスケールや SACK は今は使わない)
- `Segment::seq_len`(RFC の SEG.LEN):シーケンス番号をいくつ使うか。データのバイト数に、SYN と FIN を 1 つずつ足す(SYN と FIN も確認応答してもらう必要があるので、番号を 1 つ使う)
- `checksum`:IP のアドレスはヘッダに入らないが、チェックサムには「疑似ヘッダ」として入る

```text
疑似ヘッダ:送り元アドレス(4)| 宛先アドレス(4)| 0 | 6(TCP)| TCP の長さ(2)
```

  16 ビットずつ足し、あふれた桁を下に足し戻し(1 の補数の足し算)、最後に反転する。正しいチェックサムが入ったセグメントを同じように計算すると 0 になるので、受け取る側はそれで確かめる。長さが奇数なら、最後に 0 のバイトがあるものとして足す

## 確かめたこと

- ホスト:自分で作ったセグメントを smoltcp が読み、チェックサムが合って中身も同じ。逆に smoltcp が作ったもの(知らないオプション付き)を自分で読める
- 1 ビット化けた・宛先が違う(疑似ヘッダが違う)・短すぎる・データオフセットが 5 未満か全体より長い、はどれも EINVAL
- 長さが奇数のときのチェックサム、SYN と FIN の番号の数え方

## まだのこと

- 状態遷移、再送、ウィンドウ、`Stack` へのつなぎ込み(上の 2〜4)
