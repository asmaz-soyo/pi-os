# M3-01 物理ページの割り当て

## 何をしたか

- `hal::addr`:`PhysAddr`(物理アドレス)と `VirtAddr`(仮想アドレス)を別の型にした。`PAGE_SIZE = 4096`
- `kernel::mm::frame::FrameAllocator`:RAM を 4KiB のフレームに区切って割り当てる
  - `alloc` / `alloc_contiguous(n)` / `release` / `add_ref` / `reserve`
  - フレームごとに参照カウント(`u16`)を持つ。0 なら空き

## なぜ必要か

- ページテーブル、カーネルヒープ、ユーザープロセスのメモリは、すべてフレーム単位で RAM から取ってくる
- 計画書の「入れ物だけ今」:fork のコピーオンライトでは、同じフレームを複数のプロセスが共有する。共有の数を数える参照カウントを最初から持たせておくと、後で割り当て器を作り直さずに済む

## 中で何が起きているか

- 空きの管理は「参照カウントが 0 のフレームを探す」だけの単純な方式。`hint` で前回の続きから探すので、連続して割り当てるときは速い
- `release` は参照を1つ減らし、0 になったときだけ空きに戻す
- 不正な解放(空きのフレーム、管理範囲の外、4KiB 境界でない)は `EINVAL` を返す。二重解放のようなバグを早く見つけるため
- 物理アドレスと仮想アドレスを型で分けたのは、MMU を有効にすると両方が混在し、取り違えが静かなバグになりやすいため

## 今の限界

- 空きを探すのは線形探索(最悪でフレーム数に比例)。RAM 1GB でも 26 万フレームなので当面は問題ない。遅くなったらビットマップやバディ方式に変える
