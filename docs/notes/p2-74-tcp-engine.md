# フェーズ2-74 自作 TCP(4a):接続の表

## 何をしたか

`net/tcp/engine.rs`:`Engine`。1 本の接続(`Conn`)を束ねて、IP から届いたセグメントを振り分ける。IP のことは知らず、受け取るのも返すのも「(送り元, 宛先, TCP のバイト列)」。

### 振り分け(デマルチプレクス)

```text
届いたセグメント ─→ (ローカル, リモート) の組の接続がある? ─はい→ その Conn::on_segment
                       │いいえ
                       ↓
                   SYN で、そのポートで待ち受けている? ─はい→ 子の接続(SYN-RECEIVED)を作り、待ち行列へ
                       │いいえ
                       ↓
                   RST を返す(届いたものが RST なら黙る)
```

- 1 つのポートに何本つながっても、組(4 つ組)が違うので混ざらない
- 0.0.0.0 で待ち受けていれば、どのアドレスに来た SYN も受ける。子の接続のローカルのアドレスは、SYN の宛先
- 待ち行列(backlog)がいっぱいなら、SYN を黙って捨てる。相手は SYN を再送するので、そのうちに空く(Linux と同じ)
- accept はハンドシェイクが終わった子だけを渡す

### RST の返し方(RFC 9293 の 3.10.7.1)

- 届いたものに ACK があれば、`seq = その ACK の番号` で RST。相手が「ここまで受け取った」と言った番号なので、相手のウィンドウに入り、受け入れられる
- ACK がなければ(SYN など)、`seq = 0`、`ack = 届いたものの番号 + 長さ` で RST+ACK
- RST には RST を返さない(お互いに返し合って止まらなくなる)

### 最初のシーケンス番号(RFC 6528)

```text
ISN = 4 マイクロ秒ごとに 1 進む時計 + ハッシュ(ローカル, リモート, 鍵)
```

- 時計の分:同じ組の前の接続のセグメントが遅れて届いても、番号が重なりにくい
- ハッシュの分:外から番号を当てて、なりすましのセグメントを差し込まれないように(鍵は起動のたびに違う)

### 片付け

- ソケットが閉じられた(`release`)接続は、FIN のやりとりと TIME-WAIT が終わって CLOSED になったら表から消す
- 待ち受けをやめたら(`unlisten`)、accept されていない子は RST で切る(`Conn::abort`)

## 確かめたこと(ホスト)

2 台の `Engine` を線でつないで:accept とデータ、1 つのポートへの 2 本、閉じたポートへの SYN に RST+ACK(相手は ECONNREFUSED)、どこにも当てはまらない ACK に RST、RST に RST を返さない、backlog の上限、接続ごと・鍵ごとに違う最初の番号、閉じたあとの片付け(TIME-WAIT のあとに消える)、待ち受けをやめると子が RST で切れる
