# フェーズ2-81 スレッド(1):メモリと fd 表を共有できる形に

## 何をしたか

計画書の項目8(スレッド、futex)の準備。OS 上の uv(項目7の残り)も、main を大きなスタックのスレッドで動かし、tokio を使うので、スレッドが要る。

Linux のスレッドは「同じものを共有するタスク」。clone のフラグで、何を共有するかを選ぶ:

| フラグ | 共有するもの |
| --- | --- |
| CLONE_VM | アドレス空間(メモリ) |
| CLONE_FILES | fd の表 |
| CLONE_FS | カレントディレクトリ、umask |
| CLONE_THREAD | スレッドのグループ(getpid が同じ番号を返す) |

Pi-OS も同じにする:スレッドもプロセスの表に 1 つずつ入るタスクで、メモリと fd 表を共有する。今回はその準備で、振る舞いは変えない。

- `UserMemory`:中身(`Space`:アドレス空間、マップしたページ、brk、mmap の位置)を `Arc<SpinLock<..>>` で持つ。`share()` で同じものをもう 1 つ持ち、最後の 1 つが捨てられたときにページを返す。`fork()` は今までどおり写す。`id()` は共有している中身の目印(futex の鍵に使う)
- brk と mmap の位置を、`Process` から `UserMemory` の中に移した。スレッドが別々に持つと、2 つのスレッドが同じ場所に mmap してしまう
- `FdTable`:同じく `Arc<SpinLock<..>>`。`share()` は同じ表、`clone()`(fork)は写し。fd を閉じるときは、表から取り出してロックを放してから捨てる(最後の参照なら、ソケットの FIN などの後片付けが表のロックの中で走らないように)

メソッドの形(引数と戻り値)は変えていないので、使う側(システムコール)はほぼそのまま。ロックはメソッドごとに取る。システムコールは割り込みを止めて動くので、1 つのシステムコールの途中でほかのスレッドに切り替わることはなく(眠るときを除く)、brk の「読む → 書く」がずれることもない。

## 確かめたこと

- ホスト:共有したメモリは同じページを見て、片方を捨ててもページは残り、最後に全部返る。brk と mmap の位置も共有。fork は写す。共有した fd 表は同じ表、clone は別の表
- 今までのテスト(ホスト、QEMU、互換、スナップショット)がそのまま通る
