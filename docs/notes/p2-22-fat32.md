# フェーズ2-22 FAT32 を /boot に(読み取り専用)

## 何をしたか

- `kernel::fs::fat32`:FAT32 の読み取り。ブートセクタ(BPB)を読み、FAT をたどってクラスタの鎖を読み、ディレクトリのエントリを並べる。長い名前(LFN)と、Windows NT の小文字の印にも対応。名前は大文字と小文字を区別しない。書き込みはすべて `EROFS`
- `tools/fatimg`(ホスト用のクレート):FAT32 のイメージを作る。書式は `mkfs.fat` に任せ、ファイルとディレクトリ(8.3 と LFN のエントリ、FAT の鎖、FSInfo)は自分で書く。カーネルのテストと xtask のディスク作りの両方で使い、テストでは `fsck.fat -n` に確かめさせる
- テスト用のディスク(`target/virt-disk.img`)を SD カードと同じ形にした:p1 = FAT32(34MiB、`user/bootroot` の中身)、p2 = ext2(`user/diskroot` の中身)
- 起動時に MBR を読み、FAT32(0x0c)を `/boot`、Linux(0x83)を `/mnt` にマウント
- `/bin/bootread`(C):`/boot/README.TXT`、長い名前の `/boot/config.txt`、`/boot/overlays/` の一覧を読み、書き込みが `EROFS` になることを確かめる(QEMU の結合テスト)

```
fat32: /dev/vda1 mounted on /boot
ext2: /dev/vda2 mounted on /mnt
```

## なぜ必要か

Pi は SD カードの最初のパーティション(FAT32)から、ファームウェアと `config.txt`、カーネル(`kernel8.img`)を読んで起動する。OS からこのパーティションを読めると、設定を見たり、後で書き込みに対応すればカーネルの更新もできる。ルート(`/`)は ext2 にする(計画書:シンボリックリンクとパーミッションが FAT にないため)。

## 中で何が起きているか

```
open("/boot/config.txt")
  → VFS:/boot にマウントされた Fat32 に "config.txt" を渡す
  → ルートのクラスタ(BPB の 44 バイト目、ふつう 2)から鎖をたどってディレクトリを読む
  → 32 バイトずつ見る:
       属性 0x0F → 長い名前の部品(UTF-16 で 13 文字。後ろの部分から並ぶ)
       それ以外 → 本体(8.3 の名前 "CONFIG~1TXT"、最初のクラスタ、大きさ)
     部品をつなげた "config.txt" と比べる(大文字と小文字は区別しない)
read(fd, buf, n)
  → 位置 / クラスタの大きさ 番目のクラスタまで FAT をたどる
  → データ領域の始まり +(クラスタ − 2)× クラスタの大きさ から読む
```

## つまずいたところ

- **mtools がない**:FAT のイメージにファイルを入れるふつうの道具(`mcopy`)が入っていなかった。書式だけ `mkfs.fat` に作らせ、中身は自作の `fatimg` で書き、`fsck.fat` で確かめる形にした
- **ボリュームラベル**:`mkfs.fat -n` はラベルをブートセクタとルートディレクトリの両方に書く。ルートを書き直したときにラベルのエントリを消してしまい、`fsck.fat` に指摘された
- **FAT32 の最小の大きさ**:クラスタが 65525 個以上ないと FAT32 にならない(1 クラスタ 512 バイトで約 33MiB)。テストのディスクは 38MiB になった(ファイルの中身はほとんど 0)

## まだのこと

- 書き込み(カーネルの更新に必要になったら)
- ルート(`/`)を ext2 にする(今は initramfs がルートで、ext2 は `/mnt`)
- 実機の SD カード(EMMC のドライバ)
