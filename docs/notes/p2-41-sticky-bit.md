# フェーズ2-41 VFS:スティッキービット

## 何をしたか

- `may_remove(path)`:名前を消す(unlink、rmdir)・動かす(rename の元)・置き換える(rename の先にあったもの)前の確かめ
  - 親ディレクトリに書き込みとたどる権限が要る(unlinkat はこれまで確かめていなかった)
  - 親にスティッキービット(`S_ISVTX` = 0o1000)があれば、消せるのはファイルの持ち主、ディレクトリの持ち主、root だけ(EPERM)
- テスト:/tmp(1777)で一般ユーザーが root のファイルを消す・動かす・置き換えると EPERM、自分のファイルは自由。スティッキーなディレクトリの持ち主は、中の誰のファイルでも消せる

## なぜ必要か

/tmp は誰でもファイルを作れるように 0777 にするが、それだけだと他人のファイルを消したり、同じ名前のファイルに置き換えたり(なりすまし)できてしまう。スティッキービットで「作るのは誰でも、消すのは持ち主だけ」にする。
