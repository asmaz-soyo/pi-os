# フェーズ2-07 fork、execve、wait4、シバン

## 何をしたか

- `clone`(fork の形と vfork の形):`Process::fork` がメモリを写し、開いたファイルは共有した子プロセスを作る
- `execve`:新しいユーザー空間にプログラムを読み込み、成功したときだけ古いものと差し替える。シバン(`#!インタプリタ 引数`)にも対応
- `wait4`(`WNOHANG` 付き)、`getppid`
- `ExitStatus`(`Code(n)` か `Signal(s)`):wait4 には Linux と同じ形(`n << 8`、シグナルは下位 7 ビット)で返す
- カーネルは `Action::Fork(子)` / `Action::Exec { entry, sp }` を返し、レジスタ全体を扱う部分(子のトラップフレーム、新しい入口)は boot が行う
- プロセスは「新しいユーザー空間を作る関数」(`new_space`)を持つ。ホストのテストでは偽物を使う
- `/bin/forktest`(C):fork → 子が `/bin/exit42` を execve → 親が waitpid で 42 を受け取る。`#!/bin/qjs` で始まる `/bin/greet.js` も同じように動く

## なぜ必要か

シェルは「fork して、子で execve して、親が wait する」の繰り返しで動く。フェーズ2の「fork、シェル、シバン対応」の中心。

## 中で何が起きているか

### fork

```
親:svc #0(clone, SIGCHLD)
  kernel::syscall::proc::clone → Process::fork
      新しいユーザー空間を作り、ページを1枚ずつ写す(コピーオンライトは後で)
      fd の表を複製する(中の OpenFile は Arc で共有。読み書きの位置も共有される)
  → Action::Fork(子)
boot:子のトラップフレーム = 親のフレームの写し、ただし x0 = 0
      子のタスクを作り、表に入れる。親の x0 = 子の番号
```

親と子は同じ `svc` の次の命令から続きを動かす。違うのは x0(fork の戻り値)だけ。

### execve

1. パスを正規化し、実行の権限を確かめる
2. 先頭が `#!` なら、その行のインタプリタで同じことをやり直す(`argv` = インタプリタ、引数、スクリプトのパス、元の argv の 2 番目以降)
3. 新しいユーザー空間に ELF と初期スタックを置く。ここまでで失敗したら、今のプロセスはそのまま(エラーを返すだけ)
4. 成功したら古いユーザー空間を捨てて差し替え、boot がトラップフレームを「新しい入口、新しいスタック、レジスタは 0」にする

### wait4 と終了ステータス

終わった子はゾンビとして(親の番号, 終わり方)を残す。`wait4(-1, …)` は自分の子のゾンビを探し、なければ子が生きている限り待つ(待つ間はほかのタスクに譲る)。子がいなければ `ECHILD`。
