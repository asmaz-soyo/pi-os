# フェーズ2-78 待ち行列(1):眠って待つ、パイプ

## 何をしたか

待つシステムコール(空のパイプを読むなど)は、今まで `sched::relax` で回っていた。条件を見る → だめなら譲る → すぐまた見る。待っているあいだもずっと CPU の番を使い、ほかのタスク(リアルタイムのものも)の時間を削っていた。

Linux と同じ「待ち行列(wait queue)」にした:`kernel/src/wait.rs`

```text
待つ側:  wait_event(&[&q], 期限, || 条件)       起こす側:  (状態を変える)
          1. q に自分を登録                                  q.wake_all()
          2. 条件を見る(満たされていれば終わり)
          3. 眠る(起こされるか、期限まで)
          4. 登録を外して 1 へ
```

- **登録してから条件を見る**順番が大事。逆(見てから登録)だと、見た直後・登録の前に起こされたとき、だれも起こしてくれなくなる(lost wake-up)。登録のあと・眠る前に起こされた場合は、`sched::wake` が「次の眠りをすぐ終わらせる」印を付けるので失われない(p2-69)
- 起こされても条件が満たされたとは限らない(ほかのタスクが先に読んだ、など)ので、もう一度見る
- 1 つの待ちで、いくつもの待ち行列に登録できる(あとで poll / select に使う)
- スケジューラが動いていないとき(ホストのテスト、起動の途中)は、条件を見ながら回って待つ

### パイプ

パイプ 1 本に待ち行列を 1 つ。読む側も書く側も同じ列で待ち、状態を変えた側が全員を起こす(それぞれが自分の条件を見直す):

| 起こすとき | 待っていた側 |
| --- | --- |
| 書いた | 空で読もうとしていた側 |
| 読んだ(空きができた) | いっぱいで書こうとしていた側 |
| 書く側が全部閉じた | 読む側(終わり = 0 を読む) |
| 読む側が全部閉じた | 書く側(EPIPE) |
| FIFO を開いた | 相手が開くのを待っていた側 |

### 眠っているかを見る:`/proc/<pid>/status` の State

Linux と同じく、眠っていれば `S (sleeping)`、動いている(動ける)なら `R (running)`。今までは決め打ちで R だった。

```
pi-os:/$ { sleep 1; cat /proc/$(cat /tmp/pid)/status; true; } | sh -c 'echo $$ > /tmp/pid; exec cat > /dev/null'
Name:   busybox
State:  S (sleeping)
```

## テストを作るときに見つかったこと

1. **getpid がいつも 1 を返していた**(M5 のころの決め打ちのまま。gettid と set_tid_address も)。シェルの `$$` がいつも 1 で、`/proc/$$` が引けなかった。別のコミットで直した
2. **シェルのグループの最後のコマンドは、fork せずに exec される**。`{ sleep 1; cat ... > /tmp/x; } | 右側` だと、最後の cat のリダイレクトで左側のパイプ(標準出力)が先に閉じ、右側が EOF で終わってしまう。最後に `true` を置いて、cat を fork させた(Linux でも同じ)

3. **余分な目覚めで nanosleep が早く終わった**(互換テストで見つかった)。登録してから条件を見るまでのあいだに起こされると、眠らずに済んだのに「次の眠りをすぐ終わらせる」印が残る(パイプに書いた側が、登録中の自分を起こすこともある)。その印で、あとの関係ない `nanosleep(20ms)` がすぐ終わった。待ち行列では余分な目覚め(spurious wakeup)は普通に起きるので、Linux と同じく「期限まで必ず眠る」側が眠り直す:`sched::sleep_through`(nanosleep、clock_nanosleep が使う)。`wake_all` で自分だけ起こさない、という直し方はだめ:割り込みのハンドラの中では「今のタスク」は割り込まれたタスクで、それが登録した直後・眠る前なら、起こされずに眠り込んでしまう

## 確かめたこと

- ホスト:すぐ満たされる・期限切れ(一度は条件を見る)・登録が残らない・スケジューラなしで回って待つ、status の State の形
- QEMU(両方の BSP):待ち行列で待つスレッドは、相手が 30ms 譲り続けても条件を 3 回以下しか見ず、Blocked になっている。起こすと進む
- QEMU:空のパイプを読む cat が `S (sleeping)` になる
- QEMU:印が残っていても、`sleep_through(20ms 後)` は 20ms 以上眠る
