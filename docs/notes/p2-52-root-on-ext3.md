# フェーズ2-52 ジャーナル(4):ルートを ext3 に

## 何をしたか

- QEMU virt のディスクのルート(p2)を ext3(ジャーナル付き、4MB のジャーナル)で作るようにした(`mke2fs -t ext3 -O ^dir_index -J size=4`)
  - `dir_index`(大きなディレクトリの索引、htree)は外した。Pi-OS はディレクトリに項目を足すときに索引を直さないので
- Pi-OS の中の書き込みが、実際にジャーナルを通るようになった。互換テストの 1 回の実行で、ジャーナルのトランザクションの番号が 1 から 8 に進み、終わったあとはジャーナルが空で、「要リカバリ」の印もない(`dumpe2fs -h` で確かめた)。互換テストの最後の確かめ(`e2fsck -fn` と、書いたファイルの中身)も通る

## ジャーナルのまとめ(フェーズ2-49〜52)

| | 何をするか |
| --- | --- |
| リプレイ(2-49) | マウントのとき、ジャーナルのコミット済みのトランザクションを本来の場所に書く。取り消し(revoke)を守る |
| 書く側(2-50) | 1 つの操作 = 1 つのトランザクション。表に貯め、成功したらジャーナル → コミット → 本来の場所 → ジャーナルを空に。失敗したら捨てる |
| 電源断のテスト(2-51) | 書き込みのすべての切れ目で電源を切って、リプレイ後に e2fsck がきれいで、操作が「全部か何もなしか」 |
| ルートを ext3 に(2-52) | Pi-OS が実際にジャーナルを使う |

## まだのこと

- ファイルの中身もジャーナルに書いている(`data=journal`)。書く量が 2 倍になる。Linux の既定(`data=ordered`)は、中身は本来の場所に先に書き、メタデータだけをジャーナルに書く
- 本来の場所への書き込み(チェックポイント)を、トランザクションごとにすぐ行っている
- ジャーナルのチェックサム(ext4 の `journal_csum_v3`)
