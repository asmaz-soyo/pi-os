# フェーズ2-73 自作 TCP(3):再送とタイマー

## 何をしたか

線の上ではセグメントが失われる。失われたものは、時間が来たら送り直す。`Conn` は時計を持たないので、`on_segment(seg, now)` と `dispatch(now)` に今の時刻を渡し、`poll_at()` で「次にいつ `dispatch` を呼んでほしいか」を返す(smoltcp の `poll_delay` と同じ考え)。

### 再送タイマー(RTO、RFC 6298)

- まだ確認されていないものがあるあいだ、タイマーを掛けておく。新しい ACK が来たら掛け直し、全部確認されたら止める
- 時間切れ:`snd_nxt` を `snd_una` に戻す(go-back-N)。送るものは全部 `snd_nxt` から決めるので、SYN・SYN-ACK・データ・FIN のどれでも同じ道で送り直せる
- 時間切れのたびに待ち時間を倍にする(混んでいるネットワークをさらに混ませない)。SYN は 5 回、つながったあとは 8 回送り直してもだめなら、あきらめて ETIMEDOUT

```text
SYN を送る時刻:0, 1, 3, 7, 15, 31 秒 → 63 秒であきらめる
```

### 待ち時間の決め方

往復時間 R を測り、平均(SRTT)とばらつき(RTTVAR)をなめらかに追う。

```text
最初の 1 回:SRTT = R、RTTVAR = R / 2
そのあと:  RTTVAR = 3/4 RTTVAR + 1/4 |SRTT − R|、SRTT = 7/8 SRTT + 1/8 R
RTO = SRTT + max(1ms, 4 RTTVAR) を 200ms〜60 秒に収める(最初は 1 秒)
```

- 測るのは 1 度に 1 つのセグメントだけ(送った時刻と、その終わりの番号を覚えておき、そこまでの ACK で測る)
- **Karn のアルゴリズム**:再送したものへの ACK では測らない。最初に送ったものへの答えか、再送への答えかわからないので、測ると往復時間を短く見誤る。倍にした待ち時間は、次にちゃんと測れるまでそのまま

### ウィンドウ 0 の問い合わせ(persist)

受け取る側の窓が 0 になると、送る側は止まる。受け取る側が読んで窓が開いても、それを知らせる ACK が失われると、どちらも相手を待ったまま動かなくなる(デッドロック)。そこで、窓が 0 で送るものが残っているあいだもタイマーを掛け、時間切れになったら 1 バイトだけ送る。答えの ACK に今の窓が載ってくる。

### TIME-WAIT

閉じたあと 60 秒(2MSL)待ってから CLOSED にする。最後の ACK が失われて相手が FIN を送り直してきたときに答えるためと、同じポートの組の古いセグメントが次の接続に混ざらないようにするため。

## 確かめたこと(ホスト)

失われたデータ・FIN・SYN-ACK の再送(相手の SYN の再送には SYN-ACK を送り直す)、倍々の待ち時間と ETIMEDOUT、往復 300ms の線で RTO が 300ms 近くに落ち着く・速い線でも 200ms を下回らない、Karn(再送への ACK で待ち時間が縮まない)、窓が開いた ACK が失われても問い合わせで続く、TIME-WAIT の時間切れ、何もない接続にはタイマーがない
