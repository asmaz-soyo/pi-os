# フェーズ2-65 ネットワーク(7):eth0 をスタックにつなぐ(複数のインターフェースと道の選び方)

## 何をしたか

- `net::inet` を、インターフェースを何本でも持てる形にした
  - 0 番はループバック、そのあとに `inet::attach` で足したもの(eth0 など)
  - smoltcp のソケットはインターフェースごとの SocketSet に入るので、ソケットは「どのインターフェースの、どのハンドルか」(`H`)を覚える
  - 道の選び方(`Net::route`):127/8 はループバック。それ以外は、同じネットワークにいるインターフェース、なければデフォルトルートのあるインターフェース。どれもなければ ENETUNREACH
  - bind できるのは、0.0.0.0、127/8、どれかのインターフェースのアドレス(ほかは EADDRNOTAVAIL)
  - 0.0.0.0 での待ち受け(TCP の listen、UDP の bind)は、すべてのインターフェースで待つ
- 起動時に eth0 をスタックにつなぐ。アドレスは今は QEMU の決まった値(10.0.2.15/24、ゲートウェイ 10.0.2.2)。次のステップで DHCP にする
- ネットワークを poll するカーネルのスレッド(`boot::net_poller`):だれもシステムコールで待っていないときに届いたパケットや、再送のタイマーのため。smoltcp の `poll_delay` で「次はいつ poll が要るか」を聞き、それまで眠る(急ぎがなければ 50ms)
- テスト
  - ホスト:「線」の偽デバイス(2 つの端をつないだもの)の片方をカーネルに eth として付け、もう片方で別の smoltcp をスレッドで動かして TCP と UDP のエコーサーバーにする。システムコールからつないで、行って戻ることを確かめる。道のないアドレスは ENETUNREACH
  - QEMU:`guestfwd` で 10.0.2.100:7 への接続をホストの `cat` につなぎ(エコーサーバー)、BusyBox の `nc` で virtio-net を通って行って戻ることを確かめる

## 途中でつまずいたこと

- ホストのテストのエコーサーバーが、つながる途中(SYN-RECEIVED)のソケットを「相手が閉じた」と思って閉じていた。smoltcp の `may_recv()` は SYN-RECEIVED でも false になるため。相手が閉じたかは状態(CLOSE-WAIT)で見るようにした。切り分けのため、2 つのスタックを 1 つのスレッドで交互に poll する一時的なテストを書き、スタックそのものは正しく動くことを先に確かめた
- 最初は poll のスレッドを 10ms ごとに起こしていて、リアルタイムのタスクのジッタのテストが 1 回だけ限度(5ms)を超えた。`poll_delay` に合わせて眠るようにしてからは、最大 0.3〜0.5ms

## パケットの通り道(QEMU)

```text
nc → write → inet::InetSocket → smoltcp(eth0 の Interface)
   → DevAdapter → VirtioNet::send → virtqueue 1 → QEMU(slirp)→ ホストの cat
ホストの cat → slirp → virtqueue 0 → VirtioNet::recv → smoltcp → nc の read
```

## まだのこと

- DHCP(アドレスとゲートウェイと DNS を、決まった値ではなく QEMU からもらう)
- 受信の割り込み(今は poll のスレッドが見に行く)
