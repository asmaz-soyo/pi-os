# フェーズ2-45 VFS:dentry キャッシュ

## 何をしたか

- `Vfs` に dentry キャッシュ:リンクを含まない絶対パス → (実体, 種類)。パスを 1 要素ずつたどるとき(`Vfs::child`)に、まずここを見る
  - 種類も一緒に覚える。種類は変わらないので、たどるたびに inode を読んで「ディレクトリか、リンクか」を確かめずに済む
  - 見つかったものだけを覚える(「ない」は覚えない)
  - 1024 個を超えたら全部忘れて覚え直す(簡単な上限)
- 古い項目の消し方:名前を変える操作(create、mkdir、unlink、symlink、link、rename)は全部 `Vfs` を通るので、そこでそのパスと、その下のすべての名前を消す(`forget`)。マウントしたときは全部消す
- `FileSystem::cacheable()`:覚えてよいファイルシステムだけ true(ext2、tmpfs、FAT32、initramfs)。/proc(プロセスが勝手に増えたり消えたりする)や /dev は false
- テスト:
  - 深さ 9 のパスを 2 回探すと、2 回目はディスクを 1 セクタも読まない
  - unlink、rename(ディレクトリごと)、作り直し、リンクの削除の後に、古い答えが返らない
  - 外から中身が変わるファイルシステム(/proc の代わり)は覚えない

## 深いパスを探すときに読むセクタ

| | 1 回目 | 2 回目 |
| --- | --- | --- |
| 要素ごとにルートから探し直す(フェーズ2-42 より前) | 190 | 190 |
| 前のディレクトリから探す(フェーズ2-42) | 55 | 55 |
| dentry キャッシュ | 55 | 0 |

## まだのこと

- 「ない」ことを覚える(negative dentry)。PATH を順に探すシェルや、Python の import は、ない名前を何度も探す
- LRU で少しずつ捨てる(今は上限で全部捨てる)
