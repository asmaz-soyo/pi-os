# フェーズ2-48 後ろでの書き出し(dirty expire)

## 何をしたか

- キャッシュはセクタが最初に汚れた時刻を覚える(`dirty_since`)。書き直しても変えない(書き続けられるセクタが、いつまでも書かれないのを防ぐ)
- `BlockDevice::flush_older(age)`:汚れてから `age` 以上たったものだけを書く。`PartitionDevice` は伝える。`block::flush_older_all(age)` はすべてのディスク
- カーネルのスレッド `flusher`(ディスクがあるときだけ起動):1 秒ごとに起き(`sleep_until`)、汚れてから 5 秒たったものを書く
- キャッシュの時刻は差し替えられる(`with_clock`)。テストでは 0 秒、3 秒、4 秒(書き直し)、6 秒、9 秒と進めて、書かれるものを確かめた
- 手で確かめたこと:ext2 にファイルとディレクトリを書いたあと `sleep 100` する init で起動し、12 秒後に QEMU を強制終了(終わるときの sync は走らない)。ファイルもディレクトリも残っていて、`e2fsck -fn` もきれいだった

## なぜ必要か

write-back のキャッシュは、sync されるか、追い出されるか、ふつうに終わるまでメモリにある。電源が急に切れると、それまでの書き込みが全部消える。後ろで少しずつ書けば、失うのは最後の数秒分だけになる。

## まだのこと

- ジャーナル:書き込みの途中で切れたとき(ビットマップは書いたが inode はまだ、など)にファイルシステムが食い違わないようにする
