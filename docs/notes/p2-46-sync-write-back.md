# フェーズ2-46 sync と write-back のキャッシュ

## 何をしたか

- `BlockDevice::flush`(hal):まだディスクに書いていないものを書く。既定は何もしない
- `CachedDevice::write_back`:書き込みはメモリにだけして「汚れた」印を付ける。ディスクに書くのは
  - `flush` のとき(汚れたセクタを番号の順に)
  - いっぱいで、汚れたセクタを捨てるとき(捨てる前に書く)
  同じセクタへの何度もの書き込み(ext2 のビットマップや inode の表)が 1 回で済む
- virtio-blk のディスクを write-back のキャッシュで包んだ。`PartitionDevice` は `flush` をディスクに伝える
- `kernel::block::sync_all()`:登録したすべてのディスクを `flush`
- システムコール:`sync`(81)、`fsync`(82)、`fdatasync`(83)。今はファイルごとではなく、すべてのディスクを書く
- `boot::shutdown`:ふつうに終わるとき(init が終わったあと)は、`sync_all` してから終わる。パニックのときは書かない(ロックを持ったまま止まっているかもしれないので)
- テスト:
  - キャッシュ:`flush` までディスクに書かない、汚れたセクタは捨てる前に書く、2 回目の `flush` は何も書かない
  - 互換テストの最後に、Pi-OS で ext2 のルートにファイルを書き、終わったあとのディスクを `e2fsck -fn` と `debugfs` で確かめる。終わるときの `sync` を外すと、このテストが落ちることを確かめた

## まだのこと

- 一定時間ごとに書く(Linux の dirty_expire)。今は sync するか、終わるか、追い出されるまでメモリにある。電源が急に切れると消える
- ジャーナル(書き込みの途中で切れても、ファイルシステムが壊れないようにする)
- fsync をファイルごとにする
