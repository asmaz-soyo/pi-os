# フェーズ2-10 FP/SIMD のレジスタをプロセスごとに保つ

## 何をしたか

- `TrapFrame` に q0〜q31、FPCR、FPSR を足した(832 バイト)。例外の入口で保存し、出口で戻す
- タスクの切り替え(`switch`)で、呼び出し規約で保存すべき d8〜d15 も保存する(`SavedContext` は 24 語)
- カーネル内テスト:2 つのプロセスがそれぞれ違う値を d0 / d8 / d31 に入れ、タイマの切り替えとシステムコールをはさんでも保たれる

## なぜ必要か

フェーズ2-08 の TPIDR_EL0 と同じ種類の問題。浮動小数点を使うプロセス(qjs の数値はすべて double)が同時に動くと、切り替えのたびに値が混ざる。さらに、カーネル自身もコンパイラが SIMD レジスタを使うコード(`memcpy` など)を出すので、システムコールの途中でユーザーの値が壊れうる。

## 中で何が起きているか

### 例外の出入り(ユーザーとカーネルの境目)

例外の入口で 32 本の 128 ビットレジスタ(512 バイト)と FPCR / FPSR をトラップフレームに積み、出口で戻す。カーネルの中では自由に SIMD を使ってよく、ユーザーには入ったときと同じ値で戻る。毎回 528 バイトを読み書きするので少し遅くなる。必要になったら「最初に FP を使ったときだけ保存する」(遅延保存:CPACR_EL1 でトラップさせる)に変える。

### タスクの切り替え(カーネルの中)

`switch` は関数呼び出しとして呼ばれるので、呼び出し規約(AAPCS64)で「呼ばれた側が保存する」レジスタだけを保存すればよい。整数は x19〜x30、FP/SIMD は v8〜v15 の下位 64 ビット(d8〜d15)。それ以外は呼ぶ側が壊れてよいものとして扱う。
