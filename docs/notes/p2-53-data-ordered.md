# フェーズ2-53 ジャーナル(5):data=ordered

## 何をしたか

- ファイルの中身は、ジャーナルを通さずに本来の場所に直接書く(`Inner::write_data`)。ジャーナルに書くのはメタデータ(inode、ビットマップ、ディレクトリ、間接ブロック、スーパーブロック)だけ
- 中身はトランザクションの途中で書き、コミットの前の区切り(`flush`)でディスクに届く。だから「コミット済みのメタデータが指す中身は、必ずディスクにある」
  - コミットの前に電源が切れたら:中身はディスクにあるが、どこからも指されていない(ファイルの大きさもブロックの表も古いまま)ので、見えない
- 新しく確保したブロックは 0 で埋める(前の持ち主の中身が見えないように)。その 0 はトランザクションの表に入っているので、中身を直接書くときは表から外す。外さないと、あとのチェックポイントで表の 0 が中身を上書きしてしまう
- テスト:200KB のファイルを書いたときのセクタの書き込み回数

| | 書き込み(中身は 400 セクタ) |
| --- | --- |
| data=journal(フェーズ2-50) | 862 |
| data=ordered | 460 |

電源断のテスト(すべての書き込みの切れ目で電源を切る)も、そのまま通る

## data=ordered で守られないこと

すでにあるブロックを上書きする書き込みは、途中で切れると新しい中身と古い中身が混ざることがある(Linux の data=ordered と同じ)。守られるのは「メタデータの食い違いがない」ことと「確保したばかりのブロックの、前の持ち主の中身が見えない」こと
