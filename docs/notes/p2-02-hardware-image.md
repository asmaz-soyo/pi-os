# フェーズ2-02 実機用イメージの終わり方

## 何をしたか

- `boot` に `semihosting` feature を足した。有効ならセミホスティングで QEMU を終了し、無効なら「system halted (status N)」と出して `wfe` で止まる
- `bsp-qemu-virt` は常に有効。`bsp-raspi3` は既定で有効(QEMU で使うため)
- `cargo xtask build` の実機用イメージは `--no-default-features --target-dir target/hw` でビルドし、`target/hw/kernel8.img` にする
- スナップショット `raspi3-hw`:実機用イメージを、実機と同じくセミホスティングなしで QEMU に読ませ、最後まで表示して止まる(10 秒の `timeout` で終わる = 終了コード 124)ことを確かめる

## なぜ必要か

これまでのカーネルは、最後(とパニックのとき)にセミホスティングの `hlt #0xf000` で QEMU を終了していた。実機にはこの仕組みがないので、`hlt` は未定義命令の例外になる。例外の報告のあとでまた `hlt` を実行して、止まり方が分からなくなっていた。実機に持っていく前に、QEMU の上で見つけて直した。

## 中で何が起きているか

- feature は「QEMU で使うか、実機で使うか」というビルドの違いで、ボードの違いではない。同じ raspi3 の BSP から2種類のイメージを作る
- 実機用は別の target ディレクトリでビルドする。同じディレクトリだと、QEMU 用のテストのビルドと実機用のビルドが互いに上書きし合う
