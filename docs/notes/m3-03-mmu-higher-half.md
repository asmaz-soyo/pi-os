# M3-03 MMU の有効化と higher half 配置

## 何をしたか

- カーネルを仮想アドレス `0xFFFF_0000_0000_0000 + 物理アドレス` で動くようにリンクした(higher half)
- `_start` で起動用のページテーブルを作って MMU を有効にし、上位アドレスへ飛ぶようにした
- Rust に入ったら、フレーム割り当て器でカーネルのページテーブルを作り直して切り替える(`boot::init_memory`)
  - RAM 全体:線形マップ、読み書き可・実行不可
  - カーネルのイメージ:読み書き・実行可(後で細かく分ける)
  - デバイス:デバイス属性
  - 下位アドレス(TTBR0)は空のテーブルにした。ユーザー空間のために空けてある
- `boot` クレートを作り、初期化の順番・例外の受け口・パニックの処理を2つの BSP で共通にした。BSP は `Board` トレイト(定数とドライバ)を実装するだけになった
- カーネル内テスト:上位アドレスで動いていること、MMU が有効で RAM が線形マップに見えること、低いアドレスがマップされていないこと、割り当てたフレームに読み書きできること

## なぜ必要か

- 計画書の「最初から作る」4項目の1つ(アドレス空間)。後から配置を変えると、すべてのポインタの前提が変わる
- ユーザープログラム(musl の静的リンク)は低いアドレス(0x40_0000 付近)にリンクされている。カーネルが上位にいれば、ユーザー空間とぶつからない。Pi 3 は RAM が物理アドレス 0 から始まるので、恒等マップのままだと衝突する
- MMU を有効にすると RAM が「通常メモリ」属性になり、キャッシュが効き、スピンロック(排他ロード/ストア)が実機でも正しく動く(M1 で書いた注意が解消した)

## 中で何が起きているか

### 2つのアドレス

| | 例(virt) | 誰が使う |
| --- | --- | --- |
| 物理アドレス(LMA) | `0x4008_0000` | QEMU やファームウェアが ELF / kernel8.img を読み込む場所 |
| 仮想アドレス(VMA) | `0xFFFF_0000_4008_0000` | リンカがコードの中の番地を決めるときに使う |

リンカスクリプトの `AT(ADDR(...) - KERNEL_VBASE)` で両者を分けている。ELF の入口(`_start_phys`)は物理アドレスにしてある。MMU が無効な状態で飛んでくるため。

### MMU を有効にするまでの綱渡り

`_start` は物理アドレスで動いているのに、シンボルは上位の仮想アドレスでリンクされている。

- `adrp x1, シンボル` は「今の PC からの相対」で番地を求めるので、物理アドレスが得られる → MMU 有効化前はこちらだけを使う
- `ldr x1, =シンボル` はリンク時の絶対番地(上位アドレス)になる → MMU を有効にしてから、上位へ飛ぶときに使う

### 起動用ページテーブルの工夫

- 上位アドレス `0xFFFF_0000_xxxx_xxxx` の L0 / L1 の添字は、物理アドレスの添字と同じ(上位 16 ビットは添字に使われない)
- そのため、1 組のテーブルを TTBR0(恒等マップ)と TTBR1(上位)の両方に入れれば、MMU を有効にした瞬間も、上位に飛んだあとも、同じ命令列が動き続ける
- カーネルのある 1GiB だけを 2MiB ブロック 512 個で覆う。Pi 3 ではペリフェラル(0x3F00_0000〜)が同じ 1GiB にあるので、`BOOT_DEVICE_START` から上はデバイス属性にする

### システムレジスタ

| レジスタ | 値 | 意味 |
| --- | --- | --- |
| MAIR_EL1 | `0xff04` | 属性 0 = Device-nGnRE、属性 1 = 通常メモリ(Write-Back) |
| TCR_EL1 | `0xB5103510` + IPS | 両方 48 ビット、4KiB グラニュール、キャッシュ可、内部共有 |
| TTBR0_EL1 / TTBR1_EL1 | L0 テーブルの物理アドレス | 下位 / 上位アドレスの変換表 |
| SCTLR_EL1 | M, C, I を立てる | MMU、データキャッシュ、命令キャッシュを有効化 |

テーブルを切り替えたら `tlbi vmalle1`(TLB の全消去)と `dsb` / `isb`(完了を待つ)を忘れない。

### Rust 側の作り直し(`boot::init_memory`)

1. カーネルのイメージの後ろから RAM の終わりまでをフレーム割り当て器に渡す。参照カウントの表はその先頭に置く
2. 新しい L0 テーブルを作り、`kernel::mm::layout::kernel_mappings` の一覧どおりにマップする(一覧の作り方はホストでテスト済み)
3. TTBR1 を新しいテーブルに、TTBR0 を空のテーブルに切り替える

## 実機について

- 起動用のマップでは、Pi 3 のペリフェラルをデバイス属性にしてから MMU を有効にしている
- 実機での確認はまだしていない
