# フェーズ2-08 TPIDR_EL0(ユーザーのスレッドポインタ)をプロセスごとに保つ

## 何が起きたか

シェルから `hello` を動かしたあとに `qjs` を動かすと、raspi3b でシェル自身が落ちた(virt では起きなかった)。

```
[pi-os] user fault: data abort (lower EL): translation fault level 3, read at pc 0x10135d8, address 0x1139c14
```

## 原因の追い方

1. フォールトしたのはシェル(pid 4)。`pc 0x10135d8` はシェルのコード、`0x1139c14` はシェルのイメージの外で、qjs のスレッド情報(`set_tid_address(0x1139bb8)`)のすぐ近く
2. シェルのページは誰とも共有されておらず、カーネルスタックのあふれもなかった(スタックの一番下に目印を書いて確かめた)
3. 逆アセンブルすると、落ちた命令の直前に `mrs x25, TPIDR_EL0`(musl が TLS と errno の場所を求める)があった

TPIDR_EL0 はユーザーが自由に書けるレジスタで、musl は起動時に自分のスレッド情報のアドレスを入れる。カーネルはこれをタスクの切り替えでも例外の出入りでも保存していなかったので、qjs が入れた値のままシェルに戻り、シェルが qjs の TLS を読んでいた。virt で起きなかったのは、切り替えのタイミングの違いでたまたま表に出なかっただけ。

## 直し方

- `TrapFrame` に `tpidr_el0`(と 16 バイト境界のための詰め物)を足し、例外の入口で保存、出口で戻す(304 バイト)
- fork の子はトラップフレームの写しから始まるので、親と同じ値を受け継ぐ。exec はフレームを 0 にするので、新しいプログラムは 0 から始まる(Linux と同じ)
- カーネル内テスト:2 つのプロセスがそれぞれ違う値を TPIDR_EL0 に入れ、タイマで何度も切り替えられたあとも自分の値のままであることを確かめる(直す前は virt でも失敗した)

## 学んだこと

「プロセスごとに違う CPU の状態」は汎用レジスタだけではない。ユーザーが書けるシステムレジスタ(TPIDR_EL0、FP/SIMD のレジスタ、FPCR / FPSR など)も、切り替えのたびに保存する必要がある。FP/SIMD のレジスタはまだ保存していないので、浮動小数点を使うプロセスが同時に動くと同じ種類の不具合が起きる。次のステップで直す。
