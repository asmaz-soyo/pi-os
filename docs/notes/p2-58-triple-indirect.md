# フェーズ2-58 ext2:3 段の間接ブロック(64MB より大きなファイル)

## 何をしたか

- 書くとき(`block_for_write`)に 3 段の間接ブロック(inode の 15 個目のブロック番号)を使えるようにした。1KB のブロックでは、直接 12 + 1 段 256 + 2 段 65536 ブロック(約 64MB)までしか書けず、その先は EFBIG だった(読むほうは前から対応していた)
- 切り詰め(`free_from`)を、1 段・2 段・3 段を同じ形で扱う再帰の関数 `free_indirect` に書き直した:受け持つ範囲のうち、残す位置から先のブロックを返し、まるごと要らなくなった間接ブロック自身も返す
- テスト:2MB の小さなディスクに、70MB の位置へ 7 バイト書く(間は穴:ブロックを使わない)。読み戻し、穴が 0 で読めること、大きさ、`e2fsck`。0 に切り詰めると 3 段の間接ブロックまで全部返ること(`e2fsck`)

## ファイルの大きさの上限(1KB のブロック)

| | ブロック | 大きさ |
| --- | --- | --- |
| 直接 | 12 | 12KB |
| 1 段 | 256 | 256KB |
| 2 段 | 65,536 | 64MB |
| 3 段 | 16,777,216 | 16GB |

今は inode の大きさの上位 32 ビット(`i_size_high`)を普通のファイルで使うので、4GB を超えても大きさは正しく持てる
