# フェーズ2-01 資格情報と権限の確認(ADR-0005 の入れ物)

## 何をしたか

- `kernel::cred::Credentials`:プロセスの実 / 実効のユーザー ID・グループ ID と補助グループ。`Process::cred`(init は root)
- `kernel::cred::Credentials::check(stat, Access)`:パーミッションのビットで読み・書き・実行を許すかを決める
- `Stat` に所有者(`uid`、`gid`)を足した。initramfs は tar のヘッダの値を使う。`fstat` は `st_uid` / `st_gid` を返す
- `openat` は開く前に権限を確かめる。プログラムの実行も、実行ビットを確かめる
- `getuid` / `geteuid` / `getgid` / `getegid` はプロセスの値を返す
- `/etc/passwd`、`/etc/group`(今は root だけ)

## なぜ必要か

ADR-0005 で「ユーザーを作成できる複数ユーザー方式」に決めた。ユーザーを実際に作れるのは、書けるファイルシステムと fork / exec ができてから。その前に、権限を確かめる仕組みを入れておくと、後からファイルシステムやシステムコールを足すたびに確認を書き足す必要がない。

## 中で何が起きているか

```
mode = 0o640(rw- r-- ---)、所有者 uid 1000 / gid 100

euid == 1000 か?  → はい:所有者の 3 ビット(rw-)だけを見る
egid か補助グループに 100 があるか? → はい:グループの 3 ビット(r--)だけを見る
どちらでもない    → その他の 3 ビット(---)を見る
```

- 当てはまった区分の3ビットだけを見る。所有者に読みがなく、グループに読みがあっても、所有者本人は読めない(Linux と同じ)
- 実効 ID(euid / egid)で判定する。setuid のプログラムで効いてくる
- root(euid 0)は読み書きを通り抜けるが、実行は「どれかの実行ビットが立っている」ときだけ
