# フェーズ2-42 VFS:パスのたどり方を速く

## 何をしたか

- `FileSystem::lookup_child(dir, dir_path, name)`:すでに見つけたディレクトリ `dir` の中から `name` を探す。既定はこれまでどおりパスで探す(`lookup(dir_path/name)`)
- ext2 は `lookup_child` を自分で持つ:`dir` を `Ext2File` に戻し(`as_any`)、その inode のディレクトリの中だけを探す(`Inner::lookup_in`)
- `Vfs::walk`(`resolve_path` の中身):たどっている途中のディレクトリの実体を覚えておき、次の要素はその中から探す。たどり着いた実体も返すので、`lookup` は最後にもう一度ルートから探さずに済む
  - マウントポイントをまたぐとき、`..` のあと、絶対のシンボリックリンクのあとは、マウントの表から探し直す
- テスト:読んだセクタを数えるディスクで、深さ 9 のパス(`/a/b/c/d/e/f/g/h/file`)を探す

| | 読んだセクタ |
| --- | --- |
| これまで(要素ごとにルートから探し直す) | 190 |
| `lookup_child` で前のディレクトリから | 55 |

## なぜ遅かったか

シンボリックリンクを正しく追うため、VFS はパスを 1 要素ずつ確かめる。ところが各要素を「ルートからのパス」でファイルシステムに聞いていたので、ext2 は `/a`、`/a/b`、`/a/b/c`、… とそのたびにルートからたどり直していた。深さ d なら d(d+1)/2 回ディレクトリを読む。

## まだのこと

- dentry キャッシュ(名前 → 実体の表をメモリに置き、同じパスを何度も探すときにディスクを読まない)。rename や unlink での古い項目の消し方を決める必要がある
- ext2 の inode とディレクトリのブロックのキャッシュ(今は毎回ディスクから読む)
