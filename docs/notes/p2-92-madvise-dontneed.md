# フェーズ2-92 madvise(MADV_DONTNEED):捨てたページは 0 に戻す

## なぜ必要か

OS の上で uv を動かす準備(p2-89 の下調べ)。uv はメモリの割り当てに jemalloc を使う。jemalloc は使わなくなったページを `madvise(…, MADV_DONTNEED)` で OS に返し、あとで同じ場所を使い回す。そのとき「DONTNEED のあとのページは 0 になっている」ことを当てにして、`calloc` に 0 で埋め直さずに渡すことがある。

今までの Pi-OS の `madvise` は何もせずに 0 を返していたので、前の中身が残ったページが `calloc` から返り、まれにプログラムが壊れるおそれがあった。

## Linux での意味

| 助言 | 意味 | Pi-OS |
| --- | --- | --- |
| `MADV_DONTNEED`(4) | 無名のプライベートなページを捨てる。次に触ると 0 のページになる | 0 で埋める(今回) |
| `MADV_FREE`(8) | 捨ててもよい。メモリが足りなくなるまで残してもよい | 何もしない(中身が残っても正しい) |
| `MADV_WILLNEED` など | 先読みなどのヒント | 何もしない |

範囲の確かめ方も Linux に合わせた:

- アドレスがページの境界にない:`EINVAL`
- 長さはページの単位に切り上げる(`PAGE + 1` は 2 ページ)。長さ 0 は何もしない
- マップされていないページを含む:マップされている部分には助言を当ててから `ENOMEM`(カーネルの `madvise_walk_vmas` と同じ)
- `PROT_NONE` で取っておいただけの場所:捨てる中身がないだけで、エラーにしない

## 作り

```
madvise(addr, len, MADV_DONTNEED)
  → syscall::mm::madvise   境界の確かめ、長さの切り上げ
  → UserMemory::discard    ページごとに:
                             マップ済み → フレームを 0 で埋める(権限はそのまま)
                             予約だけ   → 何もしない
                             どちらでもない → 印を付け、最後に ENOMEM
```

Linux はフレームを解放し、次に触ったときのページフォールトで 0 のページを用意する(使うメモリが減る)。Pi-OS にはまだ「触ったときにページを用意する」仕組み(デマンドページング)がないので、フレームは持ったまま中身を 0 にする。プログラムからの見え方は同じで、使うメモリが減らないところだけがちがう。fork はページをすぐに写す作り(コピーオンライトなし)なので、ほかのプロセスとフレームを分け合っていることはなく、その場で 0 にしてよい。

## qemu-user とのちがい

互換テスト(`user/programs/madvise.c`)を作るとき、まずホストの `qemu-aarch64` で動かすと、マップされていないページを含む範囲が `0`(成功)になった。本物の Linux カーネルは `ENOMEM` を返す(man ページにも書いてある)。qemu-user は `madvise` を自前でまねていて、ここが本物とちがう。

互換テストは qemu-user と比べるので、このケースは互換テストから外し、カーネルのホストのテストで確かめることにした。比べる相手がいつも正しいとは限らない。

## 確かめたこと

- ホストのテスト:DONTNEED のあとは 0 で、範囲の外は残り、同じ権限で使い直せる。EINVAL、ENOMEM(マップされている部分は捨てる)、長さ 0、PROT_NONE。MADV_FREE などは中身を残す
- 互換テスト `madvise`:2 ページ(`PAGE + 1`)を捨てると 2 ページだけ 0 になり、3 ページめは残る。境界にないアドレス、長さ 0、PROT_NONE、MADV_WILLNEED の結果が Linux と同じ
