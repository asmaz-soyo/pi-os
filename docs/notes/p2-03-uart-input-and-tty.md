# フェーズ2-03 UART の受信と TTY の行規律

## 何をしたか

- `hal::console::Console::read_byte`:届いている入力を1バイト取り出す(待たない)。既定は「入力なし」
- `Pl011::read_byte`:FR の RXFE(受信 FIFO が空)を見て、空でなければ DR から読む
- `kernel::tty::Tty`:端末の行規律。canonical モード(行の編集)と raw モード
- `kernel::tty::Termios`:Linux と同じ値と並び(36 バイト)の端末の設定

## なぜ必要か

QuickJS の REPL(対話モード)や、シェル(フェーズ2で動かす BusyBox)は、端末から1文字ずつ、あるいは1行ずつ読む。UART はただのバイトの通り道なので、その上に「端末らしさ」をカーネルが作る。

## 中で何が起きているか

### canonical モード(既定)

| 届いたバイト | すること |
| --- | --- |
| `\r`(Enter) | ICRNL があれば `\n` に変える |
| 普通の文字 | 編集中の行に足し、エコーする |
| `0x7f` / `0x08`(Backspace) | 行の最後の文字を消し、`\b \b`(戻る・空白・戻る)をエコーする |
| `\n` | 行を「読めるもの」に移す。ここで初めて read が返る |
| `^D` | 行をそのまま読めるものに移す。空の行なら EOF(read が 0 を返す) |

1 回の read は 1 行(改行まで)だけを返す。

### raw モード

termios の ICANON を外すと、届いたバイトをそのまま読めるものに置く。ECHO も外せば、エコーもしない。行の編集はプログラムがする(QuickJS の REPL は自分で行を描き直す)。
