# M3-04 カーネルヒープ

## 何をしたか

- `kernel::mm::heap::Heap`:自作のアロケータ。空きブロックの連結リスト(番地順)で、first-fit と解放時の結合
- `kernel::mm::HEAP`:カーネルのビルドでだけ `#[global_allocator]` になる。`Box`、`Vec`、`String`、`format!` が使える
- 起動処理(`boot::init`)で 4MiB の連続したフレームをヒープにする
- ホストのテスト:境界合わせ、重ならないこと、再利用、使い切り、ばらばらの順で解放しても結合されること
- カーネル内テスト:`Box` / `Vec` / `format!` が使え、使い終わると空き容量が元に戻る

## なぜ必要か

- プロセス、ファイル記述子の表、VFS のノード、ELF の読み込みなど、大きさが実行時に決まるものを扱うには動的なメモリ確保が要る
- 既存のクレート(`linked_list_allocator` など)もあるが、アロケータの仕組みは OS の学習の中心の1つなので自作した

## 中で何が起きているか

```
初期状態:  [ 空き 4MiB                                          ]
確保 A:    [A][ 空き                                            ]
確保 B:    [A][B][ 空き                                         ]
解放 A:    [空][B][ 空き                                        ]   ← リスト:空(A) → 空き
解放 B:    [ 空き 4MiB                                          ]   ← 前後と隣り合うので1つにまとまる
```

- 空きブロックの先頭 16 バイトに「大きさ」と「次の空きブロック」を書く。管理用の別の表は要らない
- 確保の単位は 16 バイト。境界合わせ(`align`)で前に余りが出たら、それも空きブロックとして残す
- 解放したブロックは番地の順の位置に差し込む。番地順なので、隣り合うかどうかは前後の1つずつを見るだけで分かる

## 注意

- 割り込みハンドラの中では確保しない。本体がヒープのロックを持っているときに割り込まれると固まる
- 確保と解放は線形探索。空きブロックが増えると遅くなる。必要になったら大きさごとの空きリスト(スラブ)を足す
