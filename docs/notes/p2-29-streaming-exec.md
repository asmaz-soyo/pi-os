# フェーズ2-29 exec でファイルを丸ごと読まない

## 何をしたか

- `kernel::exec::Image`:実行ファイルを「好きな位置から読めるもの」として扱うトレイト。`[u8]`(initramfs のメモリ)と `dyn File`(ext2、tmpfs など)に実装した
- `exec::load`:まず先頭の 64 バイト(ELF ヘッダ)を読み、プログラムヘッダの終わりまでを読む(`elf::headers_len`)。セグメントの中身は、ファイルから 1 ページ(4KiB)ずつ読んでユーザー空間に写す
- `elf::parse(先頭, ファイルの大きさ)`:セグメントは中身のスライスではなく `offset` と `filesz` を持つ
- `execve` と、カーネルが最初のプロセスを起こす `spawn_program` は、ファイルのまま渡す。シバンを調べるのは先頭の 256 バイトだけ
- テスト:64KiB のデータを持つプログラムを読み込んでも、一度に読むのは 4096 バイト以下

## なぜ必要か

これまでは exec のたびに、実行ファイル全体をカーネルのヒープ(4MB)に読んでいた。MicroPython がデバッグビルドで 6MB になったとき、ヒープが足りずにカーネルがパニックした。CPython のような大きなプログラムを動かすには、ファイルを丸ごと読まない形が要る。

## まだのこと

- デマンドページング(触ったページだけをそのときに読む)。今は起動時に全セグメントを写す
- 同じプログラムのコードのページを、プロセスの間で共有する
