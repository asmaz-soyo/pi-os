# M5-01 tar と initramfs

## 何をしたか

- `kernel::fs::tar`:ustar 形式の tar の読み取り(`entries`、`find`)。チェックサムを確かめ、壊れていたら `EIO`
- `user/build.rs`:ユーザープログラム(`programs/*.S`、`*.c`)を zig でビルドして `/bin/` に、`rootfs/` の下のファイルをそのまま入れて、initramfs(tar)を作る
- `userland::INITRAMFS`:その tar をカーネルに埋め込んだもの
- `boot::run_program("/bin/exit42", …)`:initramfs からパスでプログラムを読み込んで実行する。ないパスは `ENOENT`

## なぜ必要か

- まだディスク(SD カード)のドライバがないので、起動時に使うファイル(`qjs` と `hello.js`)をカーネルと一緒にメモリに置く。Linux の initramfs と同じ考え方
- tar を選んだのは、形式が単純(512 バイトのヘッダ + 中身の繰り返し)で、ホストの `tar tvf` でも中身を確かめられるから

## 中で何が起きているか

```
+------------------+  512 バイト
| ヘッダ           |  名前(100)、モード、大きさ(8 進数の文字列)、チェックサム、種類('0' ファイル / '5' ディレクトリ / '2' リンク)、"ustar"
+------------------+
| 中身             |  512 バイト単位に切り上げ
+------------------+
| 次のヘッダ …     |
+------------------+
| 0 のブロック × 2 |  終わりの印
+------------------+
```

チェックサムは「チェックサム欄を空白 8 個とみなした、ヘッダ 512 バイトの和」。ホストのテストでは、テストの中で tar を組み立てて使う。
