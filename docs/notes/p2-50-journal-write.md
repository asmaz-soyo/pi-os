# フェーズ2-50 ジャーナル(2):操作をトランザクションにして書く

## 何をしたか

- ext3(ジャーナルあり)では、ext2 の 1 つの操作を 1 つのトランザクションにする(`Inner::transaction`):create、mkdir、unlink、rename、symlink、link、chmod、chown、utimensat、truncate、書き込み
  - 操作の間の書き込みはディスクに書かず、表(ブロック番号 → 新しい中身)に貯める。読むときもこの表を先に見る(操作の途中で、自分が書いたものが読めるように)
  - 操作が失敗したら、表を捨てるだけ。ディスクには何も書かれない(途中まで書いて失敗、がなくなった)
  - 中でさらに呼んだら、外側のトランザクションの一部になる
- 成功したら、ジャーナルを通して書く(`Inner::commit`)。各段の間でディスクに書き終わるのを待つ(`flush`:キャッシュが順番を入れ替えないように)
  1. ジャーナルに記述ブロック(どのブロックの中身が続くか)と中身
  2. コミットブロック
  3. ジャーナルのスーパーブロックで「ここから読め」(`s_start`)と指し、ファイルシステムのスーパーブロックに「要リカバリ」の印
  4. 本来の場所に書く
  5. ジャーナルを空に戻し(番号を進め、`s_start = 0`)、印を消す
- 3 より前に電源が切れたら、ジャーナルは空のまま(本来の場所も変わっていない)。3 より後なら、次のマウントのリプレイで全部書かれる
- 中身がジャーナルの印(0xC03B3998)で始まるブロックは、印を 0 にしてジャーナルに書き、記述ブロックに「逃がした」印を付ける
- 大きな書き込みは、ジャーナルに入りきるように 128 ブロックずつのトランザクションに分ける。ジャーナルより大きなトランザクションは `ENOSPC`
- テスト:ext3 のディスクでいろいろな操作をして、トランザクションの番号が進んだこと(ジャーナルを通ったこと)、ジャーナルが空に戻ったこと、`e2fsck -fn` がきれいなことを確かめる。失敗する操作では番号が進まない

## 書く量

すべての書き込みが 2 回になる(ジャーナルと本来の場所)。Linux の `data=journal` と同じ。Linux の既定(`data=ordered`)は、ファイルの中身はジャーナルに書かず、メタデータだけをジャーナルに書く(中身を先に本来の場所に書いてから、メタデータのトランザクションをコミットする)

## まだのこと

- 電源断のテスト(次)
- 毎回すぐに本来の場所まで書いている(同期)。Linux はコミットだけ先に済ませ、本来の場所へはまとめて後で書く(チェックポイント)
