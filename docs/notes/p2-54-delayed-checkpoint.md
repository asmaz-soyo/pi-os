# フェーズ2-54 ジャーナル(6):チェックポイントを後回しにする

## 何をしたか

- 1 つの操作ごとに行うのは「ジャーナルへのコミット」まで(`Inner::commit`)。本来の場所への書き込み(チェックポイント、`Inner::checkpoint`)は、次のときにまとめて行う
  - ジャーナルの空きが足りなくなったとき
  - `sync` / `fsync` / `fdatasync`(VFS の `sync` → 各ファイルシステムの `FileSystem::sync`)
  - 後ろで書き出すスレッドが 5 秒ごとに
  - ふつうに終わるとき
- コミットはログの続きに書く(毎回先頭に戻さない)。ジャーナルが空のときだけ、「要リカバリ」の印を立ててから、スーパーブロックで最初のトランザクションを指す。チェックポイントしたら、ジャーナルを空に戻す
- コミット済みでまだ本来の場所に書いていない中身は、メモリの表(`JournalState::committed`)に置き、読むときはディスクより先に見る
- ファイルの中身を直接書く(data=ordered)ブロックが、ジャーナルに古いメタデータとして残っていたら、先にチェックポイントする。残したまま電源が切れると、リプレイが古いメタデータでファイルの中身を上書きしてしまうため(Linux は取り消し(revoke)のレコードで防ぐ)

## 書き込みの回数(続けて 30 個のファイルを作り、sync)

| | セクタの書き込み |
| --- | --- |
| 毎回チェックポイント(フェーズ2-53) | 900 |
| まとめてチェックポイント | 444 |

ビットマップ、inode の表、ディレクトリのブロックは、作るたびに書き換わる。毎回本来の場所に書くと 30 回、まとめれば 1 回で済む

## テスト

- 30 個作ったときの書き込みの回数
- sync しないで電源が切れても(ジャーナルにしかない)、次のマウントのリプレイで全部見える
- 電源断のテスト(すべての書き込みの切れ目)も通る。ジャーナルに複数のトランザクションがたまった状態からのリプレイも含むようになった
