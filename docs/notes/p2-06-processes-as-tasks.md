# フェーズ2-06 プロセスをタスクとして動かす、プリエンプション

## 何をしたか

- `kernel::process::ProcessTable`(`PROCESSES`):動いているプロセスと、終了ステータスだけが残ったゾンビ。`take` / `put_back` / `exit` / `try_wait`
- ユーザープロセスはそれぞれ自分のタスク(カーネルスタック)で動く。`boot::spawn_user` / `spawn_program` でタスクを作り、`boot::wait` で終わるのを待つ
- タスクの入口(`user_task_entry`)で TTBR0 をそのプロセスのものにし、`enter_user_noreturn` でトラップフレームから EL0 に入る
- `exit` やフォールトでは、プロセスをゾンビにしてタスクを終える(M4 の setjmp / longjmp 方式は使わなくなった)
- タスクを切り替える直前に、次のタスクのユーザー空間(なければ空のテーブル)を TTBR0 に入れる(`Platform::before_switch`)
- プリエンプション:タイマのティックで「切り替えが必要」の印を付け、ユーザーに戻る直前(`before_return_to_user`)に譲る
- `boot::kill(pid, sig)`:保留中のシグナル(今は強制終了だけ)。ユーザーに戻る直前に、終了ステータス 128 + sig で終える
- 入力を待つ `read` / `pselect6` / `ppoll` は、待つ間ほかのタスクに譲る(`sched::relax`)
- カーネル内テスト:終わらないループのプログラムを 2 つ動かしても、カーネルとほかのプログラムが動き、`kill` で終わらせられる

## なぜ必要か

fork したプロセスやシェルの子プロセスを同時に動かすには、プロセスごとにカーネルスタックと保存した文脈が要る。また、終わらないプログラムが CPU を独り占めしないよう、タイマで強制的に切り替える必要がある。

## 中で何が起きているか

### プリエンプションは1か所で

```
EL0 でループ中のプロセス A
  ↓ タイマ割り込み(IRQ、下の EL から)
IRQ ハンドラ:ティックを数え、request_resched() で印を付ける
  ↓
before_return_to_user():印があれば yield_now() → プロセス B やカーネルのタスクへ
  ……(しばらくして A の番が戻ってくる)
  ↓
exception_return から eret → A のループの続き
```

切り替えるのは「ユーザーに戻る直前」だけ。カーネルの中の途中(ロックを持っているかもしれない場所)では切り替えないので、カーネルのコードはプリエンプションを気にしなくてよい(CLAUDE.md の「ユーザー空間に戻る直前の処理は1か所にまとめる」が効いている)。

### システムコールの間のプロセス

システムコールの間、プロセスは表から取り出して使う(`take` → `dispatch` → `put_back`)。入力を待って譲っている間も、ほかのタスクが表を使えるように。ユーザー空間のテーブル(TTBR0 に入れるもの)は表とは別に、タスクの番号で引けるようにしてある。

### 終わったプロセスの片付け

1. `PROCESSES.exit`:ユーザーのメモリとページテーブルを返し、終了ステータスだけを残す
2. `sched::exit_current`:タスクを終える。カーネルスタックは、次に誰かがスケジュールしたときに返す
3. 親の `wait`:ゾンビの終了ステータスを受け取って片付ける
