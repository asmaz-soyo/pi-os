# フェーズ2-64 ネットワーク(6):virtio-net のドライバ

## 何をしたか

- `drivers/virtio-net`:virtio-net(virtio-mmio version 2)のドライバ。`hal::net::NetDev` を実装する
  - virtqueue は 2 本:0 番が受信、1 番が送信。フレームの前に 12 バイトの `virtio_net_hdr` が付く(今は全部 0)
  - 機能の取り決め:MAC(設定から MAC アドレスを読める)と VERSION_1 だけを受け入れる
  - 受信:最初に受信のバッファ(2KiB × 8)を全部デバイスに渡しておく。届いたら used リングから「どのバッファに何バイト」を読み、ヘッダを除いて写し、同じバッファをまた渡す
  - 送信:空いている送信バッファにヘッダ+フレームを写して avail リングに載せ、知らせる。8 つとも送り途中なら `Busy`
  - 割り込みはまだ使わない(used リングを見に行く)
- 起動時の探索(`boot::probe_virtio`):virtio-mmio の枠のデバイス番号を見て、2 なら virtio-blk、1 なら virtio-net のドライバを付ける
- `kernel::net::dev`:ネットワークデバイスの登録表。見つけた順に `eth0`、`eth1`、…
- QEMU virt に virtio-net を付けた(`-netdev user -device virtio-net-device`)。QEMU のユーザーモードのネットワーク(slirp)につながり、ゲストから見ると次のようになる

  ```text
  10.0.2.2   ゲートウェイ(ホストにつながる)
  10.0.2.3   DNS
  10.0.2.15  ゲストに DHCP で配られるアドレス
  ```

- テスト:ドライバのホストのテスト(偽の MMIO と偽のデバイスで、初期化、受信バッファの用意、受信、送信、送り途中でいっぱい)、QEMU の結合テスト(eth0 が見つかり、MAC が QEMU の既定の 52:54:00:12:34:56)

## DMA のページの並べ方

```text
リングのページ                 バッファのページ i(8 枚)
  0     受信の記述子             0     受信のバッファ i(2KiB)
  128   受信の avail             2048  送信のバッファ i(2KiB)
  256   受信の used
  512   送信の記述子
  640   送信の avail
  768   送信の used
```

バッファは 2KiB でページをまたがないので、ページどうしは物理的につながっていなくてよい
