# ADR-0004: 起動処理を `boot` クレートにまとめ、BSP は `Board` トレイトを実装する

- 状態:採用
- 日付:2026-11-20

## 背景

M2〜M3 で、例外の受け口、タイマの開始、メモリの初期化、パニックの処理が、2つの BSP(qemu-virt と raspi3)にまったく同じ形で重複し始めた。CLAUDE.md の「BSP は配線だけを持つ」とも合わない。

## 決定

- AArch64 ボード共通の起動処理を `boot` クレートに置く。初期化の順番(例外ベクタ → メモリと MMU → UART と割り込みコントローラ → タイマ)を `boot::init` に明示的に書く
- BSP は `boot::Board` トレイトを実装する。中身は定数(RAM とデバイスの範囲、タイマの割り込み番号)と、ドライバの static と初期化だけ
- `#[panic_handler]` と `kernel_main` は BSP のバイナリクレートに残す(テストビルドでは `ktest` のパニック処理に差し替えるため)

## 理由

- 初期化の順番を1か所で読める(学習しやすい)
- ボードの追加が「`Board` を実装する」だけになる
- ジェネリクス(`init::<B>()`)で静的に解決するので、実行時のコストはない(ADR-0002 の方針どおり)

## 影響

- `boot` はカーネルのビルド専用(ホストではビルドしない)
- AArch64 以外のアーキテクチャを足すときは、同じ形の別クレートが必要になる
