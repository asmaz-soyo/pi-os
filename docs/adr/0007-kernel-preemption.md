# ADR-0007: カーネルのプリエンプションは、ロックの数(preempt_count)で守る

- 状態:採用
- 日付:2026-11-27

## 背景

今までは、タスクの切り替えはユーザー空間に戻るときにしか起きなかった。カーネルのスレッド(ネットワークの poll、ディスクの書き出し)は、自分から眠るまで走り続ける。DHCP を入れたとき、smoltcp の poll が続けて走り、リアルタイムのタスクの遅れが 7.6ms になった(p2-66)。そのときは「1 回起きたら 1 巡だけ」で逃げたが、どこかのカーネルのスレッドが長く回れば、また同じことが起きる。

## 決定

- カーネルを実行中に割り込みが来て、切り替えが要る(`take_resched`)なら、割り込みから戻る直前に切り替える(`Handler::before_return_to_kernel`)
- ただし、スピンロックを持っているあいだは切り替えない
  - `kernel::sync::SpinLock` を `spin::Mutex` の別名から、自前の型(中身は `spin::Mutex`)にした。`lock` で `preempt_count` を 1 増やし、印(guard)を離すと 1 減らす
  - 切り替えるのは `preempt_count() == 0` のときだけ
  - デバッグのビルドでは、ロックを持ったまま `schedule` を呼ぶとパニックする(数が次のタスクに持ち越されるため)
- 数は今はカーネル全体で 1 つ(動くコアが 1 つなので)。コアを増やすときは、コアごとに持つ
- システムコールの処理は割り込みを止めたまま走るので、今回切り替わるのはカーネルのスレッドと起動のタスクだけ

## 理由

- 持ったまま切り替わると、次のタスクが同じロックを待って回り続け、持ち主に順番が回らない(`spin::Mutex` は待つあいだ CPU を手放さない)。数で守るのは Linux と同じやり方で、ロックの使い方を変えずに済む
- 他の案
  - ロックのあいだ割り込みを止める:割り込みの遅れが、ロックを持つ時間だけ延びる。ネットワークの poll(数 ms)のあいだ、タイマも止まる
  - 切り替えてよい場所をコードに書く(`cond_resched` の印を置く):置き忘れると今と同じになる

## 影響

- ロックを持っている時間は、今までどおり切り替わらない。smoltcp の poll は NET のロックの中なので、「1 巡だけ」はまだ要る
- 割り込みのハンドラから `SpinLock` を使うと、数がいったん増えて戻る(釣り合っている)
- 割り込みを許したまま走るので、割り込みのハンドラも取るロックは割り込みを止めて取る必要がある(ADR-0010)
