# ADR-0005: 権限モデルは複数ユーザー(ユーザーを作成できる)にする

- 状態:採用
- 日付:2026-11-21

## 背景

計画書の未決事項「権限モデルを単一ユーザーにするか」。フェーズ1の実装では、プロセスは常に root(uid 0 / gid 0)として動き、`getuid` などは 0 を返している。ファイルシステムはすべて読み出し専用で、権限の確認はしていない。

## 決定

Linux と同じ形の複数ユーザーの権限モデルにする。ユーザーを作成できるようにする。

- プロセス(タスク)は実ユーザー ID・実効ユーザー ID・グループ ID(と補助グループ)を持つ
- ファイルは所有者・グループ・パーミッション(rwx × 所有者 / グループ / その他)を持ち、VFS が `open` などで確かめる
- uid 0(root)は確認を通り抜ける
- ユーザーの一覧はユーザー空間のファイル(`/etc/passwd`、`/etc/group`)に置き、カーネルは番号だけを扱う(Linux と同じ分担)
- ユーザーを作るのはユーザー空間の道具(`useradd` 相当)。カーネルに必要なのは、書けるファイルシステムと `setuid` / `setgid` などのシステムコール

## 理由

- Linux 互換(ADR-0001)を保つと、musl や BusyBox の `id`、`su`、`ls -l` などがそのまま動く
- 権限の確認は OS の学習の大事な題材の1つ
- 計画書の「入れ物だけ今」(タスクに uid/gid、VFS に確認関数)の方針と矛盾しない。入れ物の上に、本物の確認を足していく

## 影響

- 当面(フェーズ1の続き):プロセスに uid / gid などのフィールドを持たせ、VFS に権限の確認関数を置く。最初は root だけなので結果は変わらない
- ユーザーを実際に作れるのは、書けるファイルシステム(tmpfs、ext2)と、ユーザーを切り替えるプロセス(fork / exec、ログイン)ができてから(フェーズ2以降)
- `/etc/passwd` の uid 0 のユーザーとして init を動かす
