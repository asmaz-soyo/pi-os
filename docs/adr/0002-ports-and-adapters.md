# ADR-0002: ポート&アダプター構造を採用する

- 状態:採用
- 日付:2026-11-20

## 背景

ボードは実機の Pi 3B(`raspi3`)と開発用の QEMU `virt`(`qemu-virt`)の2つ。カーネルのコア(メモリ管理、スケジューラ、VFS)は、TDD のためにホストの `cargo test` で検証したい。

## 決定

- コア(`kernel/`)は `hal/` のトレイト(ポート)にだけ依存する
- ハードウェアの操作はドライバ(`drivers/`)がトレイトを実装する形で書く
- BSP(`bsp/`)は「どのドライバをどのアドレスで使うか」の配線だけを持ち、ボードごとのカーネルイメージを作る
- CPU アーキテクチャ固有の処理(起動、例外、MMU)は `arch/aarch64` に置く
- BSP はビルド時に1つに決まるので、ジェネリクスや feature で静的に解決する。実行時に決まるもの(デバイスツリーから見つけるドライバ、`File`)は `dyn Trait` を使う

## 理由

- コアをモックのポートでホストからテストできる
- ボードの追加が「ドライバを足して配線する」だけで済む
- ハードウェアの知識がコアに漏れないので、学習するときにどこを読めばよいかが分かりやすい

## 影響

- トレイトを通す分、コードの量は増える
- `arch-aarch64` と BSP のクレートはホストではビルドできないので、xtask で対象を分けて扱う
